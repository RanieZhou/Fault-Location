# 配网故障定位 Agent

10kV配电网智能故障定位系统。**通用架构**：任意拓扑（线路）通过"自定义拓扑"页上传，
不绑定任何固定线路。核心能力：

- 上传节点表+边表 → 标记哪些节点是监测点 → 设置线路参数（批量，按每公里电阻/电抗）
- 矩阵法/报警前沿算法：给定报警监测点列表，定位候选故障区段
- （可选）上传历史电气量数据（基线+事件快照）→ 系统自动从原始电压/电流读数里判断哪些
  监测点异常、自动推理报警点，不需要人工先手动指定 → 复用同一套矩阵法给出定位结果
- 前端拓扑图实时高亮报警/前沿/候选故障区段
- LLM对话式Agent：查询拓扑、定位故障、检索历史相似案例、生成巡线派工建议

## 环境要求

- Python 3.10+
- Windows / Linux 均可（开发与验证均在 Windows 上完成）
- 联网（用于调用 LLM API；离线环境下 Agent 对话功能不可用，其余功能不受影响，见下方"内网部署注意事项"）

## 快速开始

### 1. 安装依赖

```bash
python -m venv venv
```

Windows（PowerShell）激活虚拟环境：

```bash
venv\Scripts\activate
```

Linux / macOS 激活虚拟环境：

```bash
source venv/bin/activate
```

安装依赖：

```bash
pip install -r requirements.txt
```

> `requirements.txt` 里的 `pymupdf`/`pandas`/`numpy`/`openpyxl` 只有重跑 `scripts/` 目录下的
> 离线脚本（早期方案的遗留物，见下方"目录结构"）时才需要，运行 Web 服务本身用不到——
> 现在的拓扑/历史电气量数据都是通过网页上传CSV进SQLite，不再依赖Excel/CSV静态文件。
> `langchain`/`langchain-openai`/`langgraph` 同样是早期方案遗留依赖，Agent 实际用的是原生
> OpenAI function calling 实现（见 `agent/graph.py`），未使用这三个包，可安全忽略。

### 2. 登录账号

系统需要登录才能访问，默认账号密码是 `admin` / `admin`（存在 `.env` 里的 `ADMIN_USERNAME`/`ADMIN_PASSWORD`，明文存储，和LLM Key的存法一致——这是内网demo场景的挡门方案，不是生产级安全机制，正式对外使用前请改成更强的密码）。Session 存在服务端内存里，24小时过期，进程重启会导致所有人需要重新登录。

### 3. 配置 LLM（可选）

不配置也能正常使用拓扑监控、故障定位、历史事件、自定义拓扑四大功能；只有"Agent 分析"页面需要 LLM。

两种配置方式任选一种：

- **方式一**：复制 `.env.example` 为 `.env`，填入 `DEEPSEEK_API_KEY`（或 `QWEN_API_KEY` / `OPENAI_API_KEY`）
- **方式二**：直接启动服务，在网页"系统设置"页填写 API Key 并点"保存配置"（存入本地SQLite，不会上传到任何第三方）

### 4. 启动

```bash
python -m uvicorn web.app:app --host 0.0.0.0 --port 8000
```

浏览器打开 `http://localhost:8000`（局域网内其他设备用部署机器的IP访问）。

默认端口 `8000`，可在 `.env` 里设置 `HOST`/`PORT` 覆盖（这两项通过 `os.getenv` 直接读取，`web/app.py` 里的 `__main__` 入口才会用到；用 `uvicorn` 命令行直接指定 `--host`/`--port` 的方式优先级更高、更直接）。

**Windows下不建议加 `--reload`**：曾遇到杀掉主进程后其多进程reload子worker变成孤儿、继续占用端口并处理请求（代码明明改了、日志也显示reload了，但behavior还是旧的，容易误判"改动没生效"）。开发调试改完代码手动重启即可；如果一定要用`--reload`，重启前用`Get-CimInstance Win32_Process`确认没有残留的旧worker进程。

## 使用流程：上传拓扑 → 定位故障

系统里没有任何预置的固定线路，第一次使用需要先上传一个拓扑，在"自定义拓扑"页：

1. **上传节点表+边表**：两个CSV，节点表列 `node_id[,label]`，边表列 `from_id,to_id`。唯一没有入边的节点会被当成电源根节点，其余节点必须能从根节点沿边到达（树形结构，不支持环/多根）。
2. **标记监测点**：勾选哪些节点装了故障指示器/监测设备。未勾选的节点仍显示在拓扑图上，但只是结构性杆塔，不参与故障定位判断——两个监测点之间跨过的结构杆塔的线路参数会自动累加到对应的等效线段上。
3. **设置线路参数**：对勾选的边批量设置——填的是"每公里"电阻/电抗（同一种导线规格通用），系统按每条边自己的长度换算成总值，所以同一批线段长度不同也不会算错。
4. **（可选）上传历史电气量数据**：两个CSV都可选——
   - 基线数据（列 `node_id,phase,voltage_kv[,current_a]`）：正常运行时的读数，用于建立每个监测点每相的"正常"基准（均值/标准差）。
   - 事件数据（列 `event_id,timestamp,node_id,phase,voltage_kv[,current_a]`）：真实故障发生时刻各监测点的原始读数快照，同一`event_id`为一次事件。
   - 上传后可以对某次事件点击"运行推理"——系统自动判断哪些监测点偏离正常基准（判据：读数缺失/哨兵值，或电压显著低于基准），把这些点当作自动推断出的报警点，再用矩阵法给出候选故障区段。这一步**不需要人工先手动输入报警点**。
5. 配置完成后，"故障定位"页和"拓扑监控"页的下拉框会自动出现这个拓扑（标"[自定义]"前缀）；点结果卡片的"在拓扑图中查看"可以把推理/定位结果直接在拓扑图上高亮出来。

**当前限制**：Agent对话目前需要先调用 `list_topologies` 工具查询有哪些拓扑（系统提示词里已经要求LLM这么做），无法在对话里"记住"上次用的拓扑id，每次都得让LLM自己查一遍——这是有意的设计（不同拓扑各自独立上传，没有默认值这个概念更安全），但如果模型不听话瞎猜id，需要用户明确指出。

## 电气量推理算法（MVP，启发式规则）

`core/electrical_inference.py`——不是训练出的模型，是简单可解释的规则算法：

- 电压读数缺失或被识别为"哨兵值"，是判断"该相异常"最直接的信号；也会看是否显著低于该监测点的历史正常基准（默认阈值：低于基准均值15%）。
- 不用电流数值做判据——现场传感器上报的电流量级通常和真实短路电流量级对不上，强行用会给出没有数据支撑的结论。
- 综合异常评分、三相不平衡度都是启发式加权，不是精确物理量，仅用于严重程度分级排序。
- 样本量完全取决于用户实际上传了多少历史数据，可能很小，误差可能较大——这是MVP阶段的预期取舍，所有输出都会明确标注"仅供辅助参考，不替代矩阵法主结论"。
- 这一层是可选增强，找不到匹配数据或没上传过历史数据时会优雅降级（`electrical_analysis` 为 `null`，或推理接口返回"未能自动识别出异常点"），不影响矩阵法主流程。

## 历史事件数据库

历史故障事件存储在 `data/app.db`（SQLite）：

- 首次启动自动建表，空表，不预置任何数据——所有历史事件都来自实际使用（上传拓扑后跑定位/推理产生）。
- 历史表格里带橙色"实时"标签的行，标示这是系统实际使用中生成的记录。
- **想清空重来**：直接删除 `data/app.db`，下次启动会重新建一张空表（会丢失所有已上传的拓扑和历史数据，慎删）。
- 仅建议单进程运行（`uvicorn` 不加 `--workers` 参数）。当前没有做多worker并发写SQLite的保护，多worker下可能出现写冲突。

## 内网部署注意事项

这套系统面向电力公司内网环境，以下两点需要根据目标网络环境提前确认：

1. **LLM API 需要外网访问**：DeepSeek / 通义千问 / OpenAI 都是云端服务，如果部署环境完全隔离外网（无代理），Agent 对话功能将无法使用（会看到"连接失败"提示），但拓扑监控、故障定位、历史事件、自定义拓扑四大核心功能不受影响，可正常演示。
2. **图标字体从 CDN 加载**：`web/static/index.html` 里 Bootstrap Icons 通过 `cdn.jsdelivr.net` 加载。若目标环境无法访问该CDN，页面上的图标会缺失（不影响任何功能，只是视觉上少了图标），如需完全离线可用，需要把该字体文件下载后自托管到 `web/static/` 下并改用本地路径引用。

## 已知的实现遗留问题

- `.env.example` 里的 `DATA_DIR`/`OUTPUT_DIR` 两项目前**不生效**：`core/config.py` 里数据目录是硬编码的模块级常量（`ROOT_DIR/"data"`），不读取这两个环境变量。
- Agent对话的工具schema里 `line` 参数目前是自由字符串（不限定枚举），LLM需要自己先查`list_topologies`再决定传什么值——如果模型能力较弱，可能会瞎猜或用错拓扑id，这种情况下需要用户在对话里明确指出正确的拓扑名称/id。

## 目录结构

```
core/       核心引擎（自定义拓扑管理、故障定位算法、电气量推理、SQLite持久化），纯Python，不依赖Web框架
agent/      LLM Agent（多厂商适配、工具定义、tool-calling工作流、系统提示词）
web/        FastAPI 应用 + 前端静态文件（web/static/）
scripts/    早期方案遗留的离线数据处理脚本（松坪线/火龙线拓扑重建、MATLAB仿真探索等），
            现在的通用架构不再依赖这些脚本生成的数据，仅作历史参考，日常运行不需要
data/       运行时生成的 app.db（拓扑/监测点/线路参数/历史电气量数据/故障事件全部在这里）；
            另外保留了早期方案的原始参考资料（历史数据Excel、单线图PDF），现有代码不再读取
output/     早期方案遗留的静态数据（CSV），现有代码不再读取
task.md     开发进度跟踪
```

## 常见问题

- **顶部一直显示"LLM 未连接"**：还没配置 API Key，去"系统设置"页填写，或检查 `.env` 里的 key 是否正确（可以先点"测试连接"确认）。
- **拓扑监控页显示"还没有任何拓扑"**：系统没有预置任何线路，需要先去"自定义拓扑"页上传节点表+边表。
- **上传拓扑后无法用于故障定位**：检查是否至少标记了一个监测点——一个监测点都没标记的拓扑不能用于定位（管理面板里会有黄色提示）。
- **"今日告警"数字比预期大**：这个统计包含了系统实际使用产生的所有历史事件（见上方"历史事件数据库"）；正式演示前可以按上面的方法重置 `data/app.db`。
